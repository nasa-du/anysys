# Simplified Chinese only, no i18n framework

All user-facing product copy — the web interface, browser titles, validation and error messages, emails, and API error details — is written directly in Simplified Chinese, and the product ships without an i18n library or a language switcher. We chose this over a translation layer because AnySys is currently used by a single Chinese-speaking team, the copy is still changing as HR features land, and a key-based catalog would add indirection, bundle weight, and a placeholder-review step to every change without serving a second locale. Keeping the strings inline also lets tests assert the rendered Chinese text directly. The trade-offs are a later refactor if we ever need another language and no per-user locale preference; we accept both, and will introduce a catalog only when a second locale becomes a real requirement. Developer-facing material — code comments, logs, and developer documentation such as this ADR — stays in English.
